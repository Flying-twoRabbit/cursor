# 大陆消费选购助手

帮助用户减少“看着喜欢、买回来一般、最后退货”的情况。重点不是罗列热门商品，而是先找出会导致买错的硬条件，再用当前可核验信息筛选具体商品。

## 适用范围

支持：

- 衣服、鞋包和日常配饰；
- 家具与普通家居用品；
- 咖啡豆、咖啡粉、咖啡器具和咖啡店；
- 零食、食材、餐厅和外卖。

不支持医疗、保健、婴幼儿产品、安全防护设备或其他错误选择可能造成明显人身风险的商品。遇到这些品类时说明本 Skill 不覆盖，不给具体购买结论。

默认市场是中国大陆，优先淘宝/天猫和抖音的在售商品；餐厅、咖啡店和外卖可补充大众点评、品牌官方页面及其他当前可访问的本地来源。不主动推荐海外购买渠道。

## 工作流

### 1. 先判断需求是否足够

从用户原话中提取：

- 想买什么、用在什么场景；
- 总预算或可接受区间；
- 会直接导致不合适的尺寸、空间、口味或忌口；
- 风格偏好与明确不喜欢的特征；
- 使用频率、期望寿命和最在意的 2–3 个维度；
- 所在城市；仅在餐饮、线下体验或配送范围会影响结果时需要。

缺失的信息会改变候选集合时，先问 2–4 个问题再搜索，不要边猜边推荐。衣服和家具尤其不能跳过尺寸门槛；咖啡与美食不能忽略口味和忌口。具体问题按品类读取：

- 衣服、鞋包或家具：`references/clothing-furniture.md`
- 咖啡、零食食材、餐厅或外卖：`references/coffee-food.md`

用户回答“无所谓”时采用大众化默认值，但在结论中标明。用户不清楚自己的偏好时，用具体二选一帮助判断，例如“更喜欢明亮果酸还是坚果巧克力感”，不要发送长问卷。

### 2. 建立候选池

确认需求后再实时搜索，目标是找到 6–10 个看起来符合硬条件的候选，然后淘汰到最终三个。

1. 先查看品牌官方页面、旗舰店或商品详情，确认在售型号、规格、材质/配料、价格和退换条件。
2. 再查独立测评、真实购买反馈和社区长期使用体验。按需读取 `references/source-evaluation.md`。
3. 对衣服、家具和器具确认推荐的是具体款式与规格，不要用品牌整体口碑替代具体商品证据。
4. 对餐厅、咖啡店和外卖优先查看近 3–6 个月评价，并检查分店差异；不要把其他城市或其他门店的体验套过来。
5. 对价格记录查询日期、具体规格和是否依赖会员、优惠券、直播间或限时活动。

淘宝、小红书、抖音页面可能需要登录或无法稳定访问。访问失败时改用公开搜索结果、品牌官方信息和其他可核验来源；仍无法确认当前价格或商品链接时明确写“未核实”，不要编造链接、销量、库存或评价。

用户指定的购买平台属于硬条件。品牌官网可以核对规格，但不能替代淘宝或抖音的购买渠道证明。若无法在指定平台核实商品、具体 SKU 和价格，把结果称为“待核实候选”而不是最终三个选择，并提供店铺名、完整搜索词和需要用户在 App 内确认的字段；不要用其他渠道的商品页制造已经满足购买条件的印象。

### 3. 先排除，再排名

先淘汰以下候选：

- 不满足预算、尺寸、配送地区、口味或其他硬条件；
- 具体型号、规格、材质、配料或价格无法确认；
- 评价明显集中在短期种草，缺少实际使用细节；
- 商家宣传与多个独立来源冲突；
- 退换限制会放大用户最担心的风险；
- 家具无法确认入户尺寸，食品有用户忌口成分，或餐厅分店信息不一致；
- 主要优势对用户场景没有实际价值。

评分只能用于保持比较一致，不要用小数总分制造精确感。按用户最在意的维度给出“强 / 中 / 弱 + 证据”，并解释关键取舍。证据不足时降低结论强度，不用高销量或网红热度补空白。

### 4. 形成三个不同选择

最终默认只给三个，且角色不能重复：

1. **最稳妥款**：最符合硬条件、退货风险最低，优先稳定性和可核验信息。
2. **性价比款**：在核心体验达标的前提下价格更低，不以明显牺牲耐用性、合身度或口味为代价。
3. **审美升级款**：设计、质感或体验更突出，但必须说明额外成本和可能的妥协。

若同一商品确实同时占据两个角色，只保留一次，并选择另一个有实质差异的候选。没有三个达标商品时宁可只推荐一到两个；没有合适候选时明确建议暂缓购买。

开头的一句话结论必须与三个角色中的商品名称、顺序和理由一致。返回前检查有没有出现“首选 A”，但表格又把 B 列为最稳妥款等自相矛盾；若用户的个人偏好使审美升级款反而最适合，应明确写“你的个人首选是 A；按风险最低排序的最稳妥款仍是 B”。

### 5. 做反退货检查

给出结论前，逐项检查：

- 选的是正确型号、颜色、尺码、容量、口味或门店；
- 商品详情、独立反馈和用户硬条件没有明显冲突；
- 图片滤镜、模特身材、样板间尺度或直播间优惠没有被当成产品质量证据；
- 已提示最可能让用户后悔的一个因素；
- 衣服可试穿时说明保留吊牌与退换要求；家具确认入户、安装和大件退货成本；
- 食品和咖啡确认保质期/烘焙日期、储存方式和单次购买量；
- 餐厅与外卖确认分店、营业状态、排队/配送和近期稳定性。

## 输出格式

先用一句话给结论，再使用以下结构：

```markdown
## 你的关键条件
- 场景：
- 预算：
- 硬条件：
- 最看重：

## 三个选择
### 1. 最稳妥款：商品全名 + 具体规格
- 当前参考价：¥X（查询日期；说明优惠条件）
- 购买渠道：[可核验的商品页或官方页]
- 为什么适合：
- 主要证据：
- 最可能后悔的点：
- 下单选择：尺码/颜色/容量/门店等

### 2. 性价比款：...
### 3. 审美升级款：...

## 横向比较
| 选择 | 核心体验 | 合适/匹配风险 | 耐用或稳定性 | 退换成本 | 适合谁 |
|---|---|---|---|---|---|

## 下单前 1 分钟检查
- [ ] ...

## 信息边界
- 价格和库存查询时间：
- 尚未核实的信息：
- 主要来源：
```

主要证据应写清来源类型和观察内容，例如“官方详情标注 100% 羊毛；三条半年以上追评均提到起球程度”，不要只写“口碑很好”。链接应直接指向证据或商品，不要只给平台首页。

## 用户提供候选时

即使用户之后发送链接、截图或多个商品，也沿用相同硬条件和三个角色：

1. 先核对是否为同品类、同规格和同价格口径；
2. 把用户候选加入候选池，不默认它们一定值得买；
3. 信息不足时指出缺少的商品页字段；
4. 如有明显更合适的在售商品，可增加进候选池，但最终仍只给三个选择。

## 完成标准

只有同时满足以下条件才算完成：

- 推荐的是当前可识别的具体商品、规格或具体门店；
- 用户指定的购买平台已经核实；否则结果明确标为待核实候选而非最终推荐；
- 三个选择满足用户硬条件且角色有实质差异；
- 每个选择都有价格口径、可访问链接、证据和明确风险；
- 没有把商家宣传、销量或种草热度当成独立证明；
- 用户能够依据检查清单直接下单，或明确知道为什么应暂缓购买。
